# 要件定義 — 日次PDCAプランナー

## 1. 目的

月・週のPDCAで決めた目標を、1日単位の行動（何を・どれだけ・何分）に落とし込む。
その日に使える時間を入れるだけで予定ができ、終わったら実績を入れると、週の目標に対して予定通りか遅れているかがわかる状態にする。

- 利用者: 本人1人
- 利用環境: PC のブラウザ（`index.html` を直接開く）。スマホ幅でも崩れないこと
- AI・外部APIは使わない。予想は決まった計算で出す

## 2. 用語

| 用語 | 意味 |
|---|---|
| 週 | 開始日〜終了日の期間（7日に限らない。最大31日） |
| 稼働日 | 週の日付のうち、休みの日に指定していない日 |
| 項目 | 週の目標の1行。名前・単位・週の目標量・1回あたりの標準時間（分）・優先度（1〜5、1が最優先）・カテゴリー・毎日やるか |
| 毎日やる項目 | 「毎日やる」の印があり、「1日にやる量」が0より大きい項目。稼働日は先に「1日にやる量」と「今かかっている時間（分）」で予定に入れる |
| カテゴリー | 時間の割合（%）を持つ分類（例：ココナラ 50%）。全体で1つ（週ごとではない）。カテゴリーを選んでいない項目・目標は「その他」 |
| 予定 | ある日にやる項目・量・時間の一覧 |
| 実績 | ある日に実際にやった量と、かかった時間（分） |
| 締める | その日の作業が終わったことを記録する操作。進捗の判定に使う |
| 月の目標 | 月ごとの目標の1行。名前・単位・目標量・最低目標と挑戦目標（どちらも空でもよい）・実績の集め方（週の項目から／手で入力） |

## 3. 機能（フェーズ①：最小版）

### F-01 週の作成・設定
- 開始日・終了日を入れて週を作る。終了日 < 開始日、31日を超える期間、ほかの週と1日でも重なる期間は作れない（理由を画面に出す）。開始日・終了日を変えるときも同じ
- 新しい週を作るとき「今の週の項目を引き継ぐ」を選べる（実績は引き継がない）
- 週の日付を一覧で表示し、押すと休みの日に切り替わる
- 複数の週を保存し、表示する週を切り替えられる

### F-02 項目の登録
- 項目の追加・編集・削除。削除は2回押しで確定（誤操作防止）
- 入力欄: やること / 週の目標量 / 単位 / 1回の時間（分）/ 優先度 / カテゴリー / 毎日やる（印を付けると「1日にやる量」「今かかっている時間（分）」が出て、「1回の時間」は隠れる）

### F-03 今日の予定を作る
- 日付を選ぶ（初期値は今日。今日が週の外なら週の初日か最終日）
- 使える時間（時間単位、0.5刻み）を入れて「予定を作る」
- 前回入れた時間を初期値にする
- 時間内に入らなかった分は「今日は入らなかった」として量と時間を表示する
- 「時間を変えて作り直す」で予定だけ消して再計算できる（実績は残す）

### F-04 実績の記録
- 予定の各行にチェック（完了）、実績の量、かかった時間（分）
- チェックを入れたとき、量と時間が空なら予定の値を入れる
- 予定にない項目の実績も記録できる（「週の項目で予定外にやった分」）
- 週の項目にないこと（例：セミナー 2時間）を「予定外にやったこと」として、名前・かかった時間（時間、0.25刻み）・カテゴリー（カテゴリーがあるとき。未選択は「その他」）で追加・削除できる（削除は2回押しで確定）。予定を作る前の日にも記録できる
  - 「実際にかかった時間」と今日の内訳の実際の時間（選んだカテゴリー）に入る
  - 週の目標の実績・進捗・F-06 の平均には入らない
  - 名前が空、時間が0以下・24時間を超えるときは理由を出して追加しない
- 「この日を締める」/「締めを取り消す」

### F-05 進捗の表示
- 項目ごと: 実績/目標、達成率、判定、残り量と「1日あたりあと何」
- 全体: 判定、経過した稼働日、残りの作業時間、1日あたり必要な時間
- 達成率のバーに「今の時点で終わっているはずの位置」を縦線で示す

### F-06 標準時間の見直し
- 実績がある項目は「実績の平均 ○分／単位」を表示する（同じ名前の項目を全週で集計）
- 「標準時間に反映」を押したときだけ標準時間を書き換える（自動では変えない）

### F-07 データの保存とバックアップ
- すべて localStorage に自動保存する
- 「データを書き出す」で JSON ファイルを保存、「データを読み込む」で復元できる（読み込み前に上書きしてよいか画面内で確認する。`confirm()` は使わない）

### F-08 月の目標と進捗（「月」タブ）
- 開いたときは今日の日付が入っている月を表示する。前の月・次の月に切り替えられる
- 月の目標の追加・編集・削除（削除は2回押しで確定）。入力欄: 名前 / 単位 / 目標量 / 最低目標（空でもよい）/ 挑戦目標（空でもよい）/ 集め方 / カテゴリー（選んで保存し、進捗の行に表示するだけ。計算には使わない）
- 集め方「週の項目から」: 同じ名前の週の項目の実績を合計する。この月にかかる週に同じ名前の項目がなければ、そのことを表示する
- 集め方「手で入力」: 日付・量・メモを1件ずつ追加・削除する（売上、受注など）。日付はその月の中の日だけ
- 「設立済み／未設立」のようなものは、目標量1・手で入力（済んだら1を入れる）で扱う
- 進捗: 目標ごとに 実績/目標、達成率、判定、終わっているはずの位置の縦線。最低目標・挑戦目標がある行は、それぞれの達成率も出す（判定は目標に対して出す）
- 単位が目標ごとに違うので、月全体の判定は出さない
- 月の目標がまだない月では、次に何をすればよいかを出す。前の月に目標があれば「前の月の目標を引き継ぐ」ボタンを出す（写すのは名前・単位・目標量・最低目標・挑戦目標・集め方だけ。手入力の実績と振り返りメモは写さない）

### F-09 週末ごとの進み具合
- 月の中にかかる週ごとに、週の最終日の時点での月の累計（月の初日からの合計）と達成率を並べる
- 月をまたぐ週はその月の範囲で区切る（10月では 10/31 まで、11月では 11/1 から）
- 区切った最終日が今日以降の週は「途中」と表示する
- 各週に、その時点で終わっているはずの割合（区切った最終日の日にち ÷ 月の日数）を添える

### F-10 振り返りメモ
- 月ごとに「良かった点」「課題・改善点」「Act」の自由記入欄。入力するたびに保存する

### F-12 毎日すること
- 週の項目に「毎日やる」の印を付け、「1日にやる量」「今かかっている時間（分）」を入れる（例：Threads を毎日3投稿・30分）
- 初めて印を付けたときは、1日にやる量を1、今かかっている時間を1回の時間にする
- 稼働日に予定を作るとき、毎日やる項目をほかの項目より先に入れる（4.2）。休みの日は入れない
- カテゴリーを選んだ毎日やる項目の時間は、そのカテゴリーの時間の割合に含める（例：Threads 30% の中に、毎日の Threads 投稿30分が入る）
- 毎日することだけで使える時間を超えたら、入らない分を「今日は入らなかった」に出し、「毎日することだけで時間が足りません」と表示する
- 項目の欄に「週の目標量の目安：1日にやる量 × 稼働日」を出す（自動では書き換えない）
- 実績の記録と進捗は、ほかの項目と同じ。進捗の残りの作業時間と F-06 の「反映」は、1単位あたりの時間を「今かかっている時間 ÷ 1日にやる量」として扱う
  - 「今かかっている時間に反映」は、実績の平均 × 1日にやる量で書き換える

### F-13 カテゴリーと時間の割合・今日の内訳
- 「週の設定」タブの「カテゴリー」欄で、名前と時間の割合（%）を追加・編集・削除する
  - 名前が空・重複・「その他」のとき、割合が0〜100の数でないときは、理由を出して元に戻す
  - 削除は2回押しで確定する。そのカテゴリーの項目・目標は「その他」に戻す
- 割合の合計が100%でないときは注意を出す。計算では合計に対する比で分ける
- 週の項目と月の目標の編集欄で、カテゴリーを選ぶ（未選択は「その他」）
- 予定を作ったら、予定の上に「今日の内訳」を出す（4.7）
  - 帯: 各カテゴリー（その中の毎日することを含む）／毎日すること（カテゴリーなし）／その他／余り の予定時間
  - 一覧: 区分ごとの予定時間と、カテゴリーの割り当て時間。各区分の下に、その中の毎日やる項目の量と時間を「毎日」の印を付けて並べる
  - 実績を入れたら、区分ごとに「予定 ○分 → 実際 ○分」も出す
- 色はカテゴリーの並び順に6色をくり返す。ライトモード・ダークモードの両方で決める。「余り」は縞模様にする

### F-11 文章からまとめて登録（「月」タブ・「週の設定」タブ）
- 「文章からまとめて登録」の入力欄に月・週のPDCAの文章を貼り付け、「読み取る」を押す。読み取りのルールは 4.6
- 読み取った結果を確認画面に一覧で出す。登録する前に1行ずつ直せる
  - 月: 登録するか / 名前 / 目標量 / 単位 / 最低目標 / 挑戦目標 / 集め方
  - 週: 登録するか / 名前 / 目標量 / 単位 / 1回の時間 / 優先度 / カテゴリー / 毎日やる（1日にやる量・今かかっている時間）
  - 各行に元の行を添え、読めなかった行には「数値が読み取れません」と出す
- 登録先も確認画面で直せる。月は登録する月、週は開始日・終了日
  - 週の期間が今ある週とまったく同じなら、その週に登録する
  - 同じ週がなければ新しい週を作る。期間の確認は F-01 と同じで、重なるときは理由を出して登録しない
- 今の目標・項目の扱いは2つから選ぶ
  - 「同じ名前は上書きし、ない名前は追加する」（初期値）
  - 「今の目標（項目）をすべて置き換える」
  - どちらの場合も、同じ名前のものは元の目標・項目を引き継ぐので、実績は残る
  - 置き換えで消えるものは、確認画面に名前と「実績あり」かを出す
- 確認画面の初期値
  - 文章から読んだ値（目標量・単位・最低・挑戦）は文章の値。文章に最低・挑戦がなければ空（その月・週の計画は文章が正）
  - 集め方: 今の月に同じ名前の目標があればその値。なければ、その月にかかる週に同じ名前の項目があれば「週の項目から」、なければ「手で入力」
  - 月のカテゴリー: 今の月に同じ名前の目標があればその値。なければ、名前に入っているカテゴリー名
  - 週の 1回の時間・優先度・カテゴリー・毎日やる（1日にやる量・今かかっている時間）: 次の順に決める
    1. 登録先の週に同じ名前の項目があれば、その値
    2. それより前の週でいちばん新しい同じ名前の項目があれば、その値
    3. どちらもなければ 30分・優先度3・毎日やるなし。カテゴリーは名前に入っているカテゴリー名
  - 名前に入っているカテゴリー名: 項目名に含まれるカテゴリー名のうち、いちばん長いもの（英字の大文字・小文字は区別しない。例：「ココナラ競合調査」→ ココナラ）。なければ「その他」
  - 削除済みのカテゴリーを引き継いだときは「その他」にする
- 「登録する」を押して初めて、確認画面の値をすべて書いて保存する
  - 登録する行の名前が空、目標量が0以上の数でない、同じ名前が2行ある、のどれかに当たるときは理由を出して保存しない
  - 「やめる」を押すと何も変えない

## 4. 計算ルール

`src/planner.js` に実装し、テストで固定する。

実績を合計するとき（4.1 の残り量、4.3 の実績、F-06 の実績の平均）は、週の開始日〜終了日の中の日だけを数える。稼働日も、週の開始日〜終了日の中の日から休みの日を除いて数える。週の期間を短くしても期間外の日の実績・休みの日の設定はデータから消さずに残し、期間を戻せばまた使う。

### 4.1 今日の必要量
```
残り量     = max(0, 週の目標量 − その日より前の実績の合計)
残り日数   = その日より後の稼働日の数 + 1   （その日自体は休みの日でも1日と数える）
今日の必要量 = ceil(残り量 ÷ 残り日数)
```

### 4.2 予定への割り振り
項目は優先度の小さい順（同じ優先度なら登録順）に扱う。残り量が0の項目は予定に出さない。

**手順1: 毎日すること**（その日が稼働日のときだけ。休みの日は毎日やる項目を入れない）
```
量   = min(1日にやる量, 週の残り量)
時間 = round(今かかっている時間 × 量 ÷ 1日にやる量)
```
- 使える時間を超えるときは `floor(残り時間 ÷ (今かかっている時間 ÷ 1日にやる量))` だけ入れる
- 残りは「入らなかった」に回し、「毎日することだけで時間が足りません」を出す

**手順2以降: ほかの項目**（必要量は 4.1）。「入れる」とは、時間 `t` の中で、まだ入っていない必要量のうち `floor(t ÷ 標準時間)` だけ入れること。標準時間が0の項目は、時間を使わずに必要量をすべて入れる。

カテゴリーが1つもないとき:
2. 毎日することの残りの時間で、優先度順に入れる（今までの割り振り）

カテゴリーがあるとき:
2. 各カテゴリーの持ち時間（そのカテゴリーの毎日することを含む）を出す
   - `基準 = 使える時間 − カテゴリーなしの毎日することの時間`
   - 持ち時間 = `floor(基準 × 割合 ÷ 割合の合計)`
   - 毎日することだけで持ち時間を超えるカテゴリーは、持ち時間を毎日することの時間にする。基準の残りを、ほかのカテゴリーで割合どおりに分け直す（超えるカテゴリーがなくなるまでくり返す）
   - 切り捨てた端数は「余り」に入れる
3. 各カテゴリーの中で、`持ち時間 − そのカテゴリーの毎日することの時間` の範囲で、ほかの項目を優先度順に入れる。使い切らなかった時間は「余り」に入れる
4. 「余り」を、まだ入りきっていない項目に回す
   - カテゴリーの割合が大きい順（同じなら登録順）→ 最後に「その他」（未選択・削除済みのカテゴリーの項目）
   - 各カテゴリーの中は優先度順
   - 「その他」の項目は、この余りだけを使う
5. それでも入らない分は「入らなかった」に回す

予定の行には、作った時点の区分（毎日やる項目か・カテゴリー）を残す。

### 4.3 進捗の判定
```
経過日数   = 今日より前の稼働日の数 + （今日が稼働日で締め済みなら1）
             ※週の終了日を過ぎていれば稼働日の数すべて
終わっているはずの量 = 目標量 × 経過日数 ÷ 稼働日の数
```
| 条件 | 判定 |
|---|---|
| 目標量が0 | 目標なし |
| 実績 ≥ 目標量 | 達成 |
| 経過日数が0 | これから |
| 実績 ÷ 終わっているはずの量 ≥ 100% | 予定通り |
| 80%以上100%未満 | 遅れ気味 |
| 80%未満 | 遅れ |

全体の判定は、各項目の `min(実績, 目標) × 標準時間` の合計と `目標 × 標準時間` の合計で同じ表を使う。

### 4.4 例（テストに使う）
週 10/26〜11/1、11/1 は休み（稼働日6日）。10/27 の予定を作る（残り日数 = 4 + 1 = 5）。

| 項目 | 目標 | 1回 | 優先度 |
|---|---|---|---|
| 出品 | 3件 | 60分 | 1 |
| Threads | 21投稿 | 10分 | 2 |
| 学習 | 2講義 | 60分 | 3 |

- 使える時間 2時間 → 出品1件(60分)、Threads 5投稿(50分)。学習1講義(60分)は「入らなかった」
- 使える時間 5時間 → 3項目すべて入る
- 10/26 を締め済みで実績「出品1・Threads 2」、今日 10/27 → 経過日数1。出品は「予定通り」、Threads は「遅れ」、学習（実績0、経過1日）は「遅れ」

### 4.4b 例: 毎日すること・カテゴリー（テストに使う）
使える時間3時間、カテゴリー「ココナラ 50%・Threads 30%・学習 20%」。
- 毎日すること30分がカテゴリーなしのとき: 残り150分を 75分・45分・30分に分ける。学習の項目が今日の分で20分しか使わないとき、余った10分は、ココナラ・Threads の入りきっていない項目に回る
- 毎日すること30分が Threads のとき: 180分を 90分・54分・36分に分ける。Threads の54分に毎日の30分を含め、Threads のほかの項目には24分を使う
- 学習の毎日することが60分のとき: 学習の割合の分（36分）を超えるので学習は60分。残り120分を 75分・45分に分ける

### 4.5 月の集計（F-08・F-09）
- 月への振り分けは、週ではなく実績の日付で行う
- 集め方「週の項目から」: 全週の同じ名前の項目について、その週の開始日〜終了日の中、かつその月の中の日の実績を合計する
- 集め方「手で入力」: 日付がその月の中の実績を合計する
```
経過日数   = 今日より前の、その月の日の数 + （今日を締めていれば1）
             ※月が終わっていればその月の日数、まだ始まっていなければ0
             ※「今日を締めている」= 今日を含むどれかの週で、今日が締め済み
終わっているはずの量 = 目標量 × 経過日数 ÷ その月の日数
```
- 判定は 4.3 と同じ表を目標量に対して使う。挑戦目標は達成率（実績 ÷ 挑戦目標）だけを出す
- 週末ごとの進み具合: 週の期間をその月の中に区切り、区切った最終日までの月の累計で達成率を出す

例（テストに使う）: 週 10/26〜11/1 で 10/31 と 11/1 に実績がある場合、10月には 10/31 の分だけ、11月には 11/1 の分だけが入る。10月の週末ごとの進み具合では、この週は 10/26〜10/31 として表示する。

### 4.6 文章の読み取り（F-11）
`src/parser.js` に実装し、テストで固定する。

- 全角の数字・コロン・スラッシュは半角として読む
- 読む範囲
  - 【Plan】の次の行から、次の【…】の見出し（【Do】【Check】【Act】など）の手前まで
  - 【Plan】がなければ全体を読む
  - 「━」などの罫線だけの行と空行は無視する
- 見出し（【Plan】より前の行。【Plan】がなければ最初の、目標でない行）から期間を読む
  - 「M/D〜M/D」は週の開始日と終了日にする。区切りは 〜 ～ ~ - のどれでもよい
  - 「N月」はその月にする
  - 年は今日にいちばん近い年（月の差が前後6か月以内。ちょうど6か月なら前の年）
    - 例: 今日が 2026-11-03 なら、10月は 2026-10、1月は 2027-01、5月は 2026-05
    - 例: 今日が 2027-01-10 なら、12月は 2026-12
  - 週の日付も同じ決め方にする。終わりの月が始まりの月より小さいとき（12/28〜1/3）は、終わりを翌年にする
  - 期間が読めないとき、月は表示している月、週は表示している週にする
- 「・」で始まる行が1つの目標。最初の「:」（全角・半角）で名前と内容に分ける
  - 内容の中の最初の数字（カンマ・小数点付きでもよい）を目標量にする
  - 数字のすぐ後ろの言葉から、末尾の「以上」を外したものを単位にする
  - 数字の前に言葉があれば名前に付ける
    - 「各」で始まるときは「（各アカウント）」のように括弧で付ける
    - それ以外はそのまま後ろにつなげる（「フォロワー100人」なら「Threads（…）フォロワー」）
- 「→ 最低目標：」「→ 挑戦目標：」の行は、すぐ上の目標の最低目標・挑戦目標にする。週の項目ではこの2つを使わない
- 次のどれかに当たる行は数値の目標として読めない。登録のチェックを外して出し、「数値が読み取れません」と表示する
  - コロンがない
  - 数字がない
  - 単位に句読点・空白（、。, など）が入っている、または単位が8文字より長い（単位の後ろに文が続いている）
- それ以外の行は読まずに、確認画面の「読まなかった行」に出す

例（テストに使う）: 「💰 11月 収益化PDCA」の文章では、12目標を読む。売上は 30,000円で、最低 10,000・挑戦 50,000。note の行（「フォロワー50人達成後、記事制作開始」）は読めない行になる。

### 4.7 今日の内訳（F-13）
- 区分: 毎日すること（カテゴリーなし）／各カテゴリー（並び順）／その他／余り。カテゴリーを選んだ毎日やる項目は、そのカテゴリーに数える
- 予定時間: その日の予定の行を、作った時点の区分で合計する。削除済みのカテゴリーの行は「その他」に数える
- 実際の時間: その日の実績の時間を合計する。予定にある項目は予定の区分で、予定外にやった項目は今の区分で数える。予定外にやったこと（F-04）は選んだカテゴリー（未選択・削除済みは「その他」）に数える
- 割り当て時間: 予定を作ったときのカテゴリーの持ち時間（4.2 の手順2）
- 余り = max(0, 使える時間 − 予定時間の合計)
- 各区分の中の毎日やる項目は、項目ごとにも予定の量・予定時間・実際の時間を出す（予定の順。予定外にやった毎日やる項目はそのあと）
- 割り当て時間は、そのカテゴリーの毎日することを含む持ち時間
