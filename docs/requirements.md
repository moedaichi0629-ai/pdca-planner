# 要件定義 — 日次PDCAプランナー

## 1. 目的

月・週のPDCAで決めた目標を、1日単位の行動（何を・どれだけ・何分）に落とし込む。
その日に使える時間を入れるだけで予定ができ、終わったら実績を入れると、週の目標に対して予定通りか遅れているかがわかる状態にする。

- 利用者: 本人1人
- 利用環境: PC のブラウザ（`index.html` を直接開く）。スマホ幅でも崩れないこと
- AI・外部APIは使わない。予想は決まった計算で出す

## 2. 用語

| 用語 | 意味 |
|---|---|
| 週 | 開始日〜終了日の期間（7日に限らない。最大31日） |
| 稼働日 | 週の日付のうち、休みの日に指定していない日 |
| 項目 | 週の目標の1行。名前・単位・週の目標量・1回あたりの標準時間（分）・優先度（1〜5、1が最優先） |
| 予定 | ある日にやる項目・量・時間の一覧 |
| 実績 | ある日に実際にやった量と、かかった時間（分） |
| 締める | その日の作業が終わったことを記録する操作。進捗の判定に使う |
| 月の目標 | 月ごとの目標の1行。名前・単位・目標量・挑戦目標（空でもよい）・実績の集め方（週の項目から／手で入力） |

## 3. 機能（フェーズ①：最小版）

### F-01 週の作成・設定
- 開始日・終了日を入れて週を作る。終了日 < 開始日、31日を超える期間、ほかの週と1日でも重なる期間は作れない（理由を画面に出す）。開始日・終了日を変えるときも同じ
- 新しい週を作るとき「今の週の項目を引き継ぐ」を選べる（実績は引き継がない）
- 週の日付を一覧で表示し、押すと休みの日に切り替わる
- 複数の週を保存し、表示する週を切り替えられる

### F-02 項目の登録
- 項目の追加・編集・削除。削除は2回押しで確定（誤操作防止）
- 入力欄: やること / 週の目標量 / 単位 / 1回の時間（分）/ 優先度

### F-03 今日の予定を作る
- 日付を選ぶ（初期値は今日。今日が週の外なら週の初日か最終日）
- 使える時間（時間単位、0.5刻み）を入れて「予定を作る」
- 前回入れた時間を初期値にする
- 時間内に入らなかった分は「今日は入らなかった」として量と時間を表示する
- 「時間を変えて作り直す」で予定だけ消して再計算できる（実績は残す）

### F-04 実績の記録
- 予定の各行にチェック（完了）、実績の量、かかった時間（分）
- チェックを入れたとき、量と時間が空なら予定の値を入れる
- 予定にない項目の実績も記録できる（「予定外にやった分」）
- 「この日を締める」/「締めを取り消す」

### F-05 進捗の表示
- 項目ごと: 実績/目標、達成率、判定、残り量と「1日あたりあと何」
- 全体: 判定、経過した稼働日、残りの作業時間、1日あたり必要な時間
- 達成率のバーに「今の時点で終わっているはずの位置」を縦線で示す

### F-06 標準時間の見直し
- 実績がある項目は「実績の平均 ○分／単位」を表示する（同じ名前の項目を全週で集計）
- 「標準時間に反映」を押したときだけ標準時間を書き換える（自動では変えない）

### F-07 データの保存とバックアップ
- すべて localStorage に自動保存する
- 「データを書き出す」で JSON ファイルを保存、「データを読み込む」で復元できる（読み込み前に上書きしてよいか画面内で確認する。`confirm()` は使わない）

### F-08 月の目標と進捗（「月」タブ）
- 開いたときは今日の日付が入っている月を表示する。前の月・次の月に切り替えられる
- 月の目標の追加・編集・削除（削除は2回押しで確定）。入力欄: 名前 / 単位 / 目標量 / 挑戦目標（空でもよい）/ 集め方
- 集め方「週の項目から」: 同じ名前の週の項目の実績を合計する。この月にかかる週に同じ名前の項目がなければ、そのことを表示する
- 集め方「手で入力」: 日付・量・メモを1件ずつ追加・削除する（売上、受注など）。日付はその月の中の日だけ
- 「設立済み／未設立」のようなものは、目標量1・手で入力（済んだら1を入れる）で扱う
- 進捗: 目標ごとに 実績/目標、達成率、判定、終わっているはずの位置の縦線。挑戦目標がある行は挑戦目標の達成率も出す
- 単位が目標ごとに違うので、月全体の判定は出さない
- 月の目標がまだない月では、次に何をすればよいかを出す。前の月に目標があれば「前の月の目標を引き継ぐ」ボタンを出す（写すのは名前・単位・目標量・挑戦目標・集め方だけ。手入力の実績と振り返りメモは写さない）

### F-09 週末ごとの進み具合
- 月の中にかかる週ごとに、週の最終日の時点での月の累計（月の初日からの合計）と達成率を並べる
- 月をまたぐ週はその月の範囲で区切る（10月では 10/31 まで、11月では 11/1 から）
- 区切った最終日が今日以降の週は「途中」と表示する
- 各週に、その時点で終わっているはずの割合（区切った最終日の日にち ÷ 月の日数）を添える

### F-10 振り返りメモ
- 月ごとに「良かった点」「課題・改善点」「Act」の自由記入欄。入力するたびに保存する

## 4. 計算ルール

`src/planner.js` に実装し、テストで固定する。

実績を合計するとき（4.1 の残り量、4.3 の実績、F-06 の実績の平均）は、週の開始日〜終了日の中の日だけを数える。稼働日も、週の開始日〜終了日の中の日から休みの日を除いて数える。週の期間を短くしても期間外の日の実績・休みの日の設定はデータから消さずに残し、期間を戻せばまた使う。

### 4.1 今日の必要量
```
残り量     = max(0, 週の目標量 − その日より前の実績の合計)
残り日数   = その日より後の稼働日の数 + 1   （その日自体は休みの日でも1日と数える）
今日の必要量 = ceil(残り量 ÷ 残り日数)
```

### 4.2 予定への割り振り
1. 項目を優先度の小さい順（同じ優先度なら登録順）に並べる
2. 使える時間（分）から、各項目の「必要量 × 標準時間」を順に引く
3. 入りきらない項目は `floor(残り時間 ÷ 標準時間)` 件だけ入れ、残りを「入らなかった」に回す
4. 標準時間が0の項目は時間を使わずに必要量をすべて入れる
5. 残り量が0の項目は予定に出さない

### 4.3 進捗の判定
```
経過日数   = 今日より前の稼働日の数 + （今日が稼働日で締め済みなら1）
             ※週の終了日を過ぎていれば稼働日の数すべて
終わっているはずの量 = 目標量 × 経過日数 ÷ 稼働日の数
```
| 条件 | 判定 |
|---|---|
| 目標量が0 | 目標なし |
| 実績 ≥ 目標量 | 達成 |
| 経過日数が0 | これから |
| 実績 ÷ 終わっているはずの量 ≥ 100% | 予定通り |
| 80%以上100%未満 | 遅れ気味 |
| 80%未満 | 遅れ |

全体の判定は、各項目の `min(実績, 目標) × 標準時間` の合計と `目標 × 標準時間` の合計で同じ表を使う。

### 4.4 例（テストに使う）
週 10/26〜11/1、11/1 は休み（稼働日6日）。10/27 の予定を作る（残り日数 = 4 + 1 = 5）。

| 項目 | 目標 | 1回 | 優先度 |
|---|---|---|---|
| 出品 | 3件 | 60分 | 1 |
| Threads | 21投稿 | 10分 | 2 |
| 学習 | 2講義 | 60分 | 3 |

- 使える時間 2時間 → 出品1件(60分)、Threads 5投稿(50分)。学習1講義(60分)は「入らなかった」
- 使える時間 5時間 → 3項目すべて入る
- 10/26 を締め済みで実績「出品1・Threads 2」、今日 10/27 → 経過日数1。出品は「予定通り」、Threads は「遅れ」、学習（実績0、経過1日）は「遅れ」

### 4.5 月の集計（F-08・F-09）
- 月への振り分けは、週ではなく実績の日付で行う
- 集め方「週の項目から」: 全週の同じ名前の項目について、その週の開始日〜終了日の中、かつその月の中の日の実績を合計する
- 集め方「手で入力」: 日付がその月の中の実績を合計する
```
経過日数   = 今日より前の、その月の日の数 + （今日を締めていれば1）
             ※月が終わっていればその月の日数、まだ始まっていなければ0
             ※「今日を締めている」= 今日を含むどれかの週で、今日が締め済み
終わっているはずの量 = 目標量 × 経過日数 ÷ その月の日数
```
- 判定は 4.3 と同じ表を目標量に対して使う。挑戦目標は達成率（実績 ÷ 挑戦目標）だけを出す
- 週末ごとの進み具合: 週の期間をその月の中に区切り、区切った最終日までの月の累計で達成率を出す

例（テストに使う）: 週 10/26〜11/1 で 10/31 と 11/1 に実績がある場合、10月には 10/31 の分だけ、11月には 11/1 の分だけが入る。10月の週末ごとの進み具合では、この週は 10/26〜10/31 として表示する。

## 5. データ設計（localStorage）

キー `pdca-planner` に1つの JSON を保存する。

```json
{
  "schemaVersion": 2,
  "settings": { "currentWeek": "w_abc123", "lastHours": 3 },
  "weeks": {
    "w_abc123": {
      "id": "w_abc123",
      "start": "2026-10-26",
      "end": "2026-11-01",
      "offDays": ["2026-11-01"],
      "items": [
        { "id": "i_x1", "name": "ココナラ商品の出品", "unit": "件", "target": 3, "minutes": 60, "priority": 1 }
      ],
      "days": {
        "2026-10-27": {
          "hours": 3,
          "plan":    [{ "itemId": "i_x1", "qty": 1, "min": 60 }],
          "skipped": [],
          "log":     { "i_x1": { "qty": 1, "min": 75, "done": true } },
          "closed": false
        }
      }
    }
  },
  "months": {
    "2026-10": {
      "month": "2026-10",
      "goals": [
        { "id": "g_a1", "name": "Threads", "unit": "投稿", "target": 93, "stretch": null, "source": "weekly", "entries": [] },
        { "id": "g_a2", "name": "売上", "unit": "円", "target": 50000, "stretch": 100000, "source": "manual",
          "entries": [{ "id": "e_1", "date": "2026-10-31", "qty": 12000, "memo": "ココナラ1件" }] }
      ],
      "review": { "good": "", "issues": "", "act": "" }
    }
  }
}
```

- `source`: `"weekly"`（週の項目から）/ `"manual"`（手で入力。実績は `entries`）。`stretch`（挑戦目標）は空なら `null`
- `months` のキーは `YYYY-MM`。月の目標を最初に登録したときに作る
- schemaVersion の移行: v0（試作版）→ v1 → v2（`months: {}` を足す。週・設定はそのまま）

## 6. 今後のフェーズ（今は作らない）

### フェーズ②：受注案件と納期
- 案件を登録: 名前、納期、作業時間の見積もり（時間）、余裕日数（初期値1日＝納期の前日に終える）
- 予定を作るとき、案件の作業を通常の項目より先に割り振る
  - 案件の1日の必要時間 = 残り作業時間 ÷（納期 − 余裕日数 までの稼働日数）
- 納期に間に合わない見込みなら警告を出す
- 案件の作業を入れたことで入らなくなった通常の項目を表示する

### フェーズ③：PDCAとの連動
- 月の目標から週・日の量を出す（例: 月93投稿 → 1日3投稿）
- 週・月の Do／Check 欄を、今の PDCA の書式の文章で書き出す（コピーして使える形）
- 「作る・改善する」系の項目に時間の上限を設け、超えたら警告する
